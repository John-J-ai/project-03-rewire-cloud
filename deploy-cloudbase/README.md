# 国内路线 · CloudBase 静态托管部署包

> 这是「国内国外两条路」中的国内分支。Supabase 那条继续走 `rewire-cloud/` 本体；这里只解决**静态站点放在国内、链接给国内人看**的问题。
> 本包不含秘钥、不含账号，只有一个配置模板和一个资源复制脚本。

## 先看清代价（2026-11 官方口径）

| 路线 | 域名 | 备案 | 可用性 | 适合什么 |
|---|---|---|---|---|
| A. 默认域名 | `xxx.tcloudbaseapp.com` / `xxx.app.tcloudbase.com` | 不需要 | 仅开发测试；有访问频率限制、功能缺失、访问提示中间页 | 自己验证部署流程 |
| B. 自定义域名 | 自己的已备案域名 | **必须 ICP 备案** | 正式可用、可 HTTPS、可分享 | 作品集长期链接 |

两个硬事实，别踩坑：

1. **2025-10-09 之后新建的 CloudBase 环境，默认域名的「续期」机制已下线，访问提示中间页长期存在**。官方明确：浏览器直接访问静态网站，生产环境必须用自定义域名。默认域名只能拿来测流程。
2. **CloudBase 环境内办备案有条件**：个人版及以上套餐（免费体验环境不支持）、环境剩余有效期 > 6 个月、已开启「云托管固定 IP」。也就是说**免费体验环境办不了备案**。要正式链接，预算里要有「个人版套餐 + 域名年费」。

另有一条独立风险：云版的 Supabase 后端在境外，国内访问速度和稳定性不受本包控制。如果国内路线要长期正式运营，下一步应把 `supabase-schema.sql` 的两张表迁到 CloudBase 数据库并改写 REST 适配层——本包**没有做这一步**，别误以为迁到国内就自动全链路国产化了。

## 部署步骤（路线 A：先验证跑通）

```bash
# 1. 安装 CLI（全局，只装一次）
npm install -g @cloudbase/cli

# 2. 登录（会开浏览器授权；无交互环境用 tcb login --apiKeyId xxx --apiKey xxx）
tcb login

# 3. 在腾讯云开发控制台创建环境，复制环境 ID
#    本目录 cloudbaserc.json → 把 "YOUR_ENV_ID" 换成真实 envId

# 4. 生成干净的发布目录（只复制 index.html / manifest / sw / 图标）
node prepare.js

# 5. 先看变更计划，确认无误再部署
tcb deploy --dry-run

# 6. 部署
tcb deploy --yes
```

部署完在控制台「静态网站托管 → 应用部署列表」找到 `rewire-cloud`，点「访问应用」拿默认域名。
打开 `https://<默认域名>/index.html?demo=1` 可以直接看演示模式，不用填任何密钥——这是最适合发给别人预看的链接形态。

回退：从 `deploy-cloudbase/` 目录执行 `tcb hosting detail` 查域名；不要在同一个 env 里混用路径模式和另一套站点配置。

## 路线 B：正式链接（需要本人操作 + 付费）

前置条件见上文「CloudBase 环境内办备案」三条。满足后：

1. 注册域名（腾讯云 DNSPod / 阿里云均可），**域名所有者必须与备案主体一致**，并完成域名实名认证。
2. 在 CloudBase 控制台 → 对应环境 →「备案管理」→「去备案」，按 `ICP备案清单.md` 准备材料。
3. 备案通过后，控制台申请/上传 SSL 证书（免费证书可用）。
4. 静态托管详情页 →「自定义域名」→ 添加域名 → 选「应用模式」+「云开发 CDN」+ 证书。
5. 按控制台给出的 CNAME 值去 DNS 服务商加解析；同一主机记录下 CNAME 与 A/TXT 冲突，先清旧记录。
6. 等状态变「已生效」，浏览器打开 `https://你的域名/index.html?demo=1` 验证。
7. 备案号下来后，在网站页脚展示备案号并链接到工信部备案系统（合规要求，别漏）。

详细材料与流程见 [ICP备案清单.md](ICP备案清单.md)。

## 文件说明

- `cloudbaserc.json` — 新版声明式部署配置；`envId` 是唯一需要你填的字段。
- `prepare.js` — 从上级目录复制静态资源到 `site/`；不改动源目录，也不会把 `.git`、`docs/` 一起传上去。
- `site/` — 运行 `prepare.js` 后自动生成，可删可重建。

## 为什么不直接传整个 rewire-cloud 目录

上级目录里有 `.git/`、README、SQL、截图和验证脚本。声明式部署会把 `root` 下所有东西当作站点资源上传，既浪费流量又把仓库内部文件暴露到公网。所以先 `prepare.js` 收敛到 6 个必要文件。
